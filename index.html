JDK, JRE, JVM e as cinco etapas

Enunciado

Explique a diferença entre JDK, JRE e JVM. Em seguida, descreva as cinco etapas pelas quais passa um programa Java (edição, compilação, carga, verificação e execução), dizendo qual arquivo é produzido ou usado em cada uma. Por que se diz que um programa Java é portável?

Resposta

JVM (Java Virtual Machine) é a máquina virtual que carrega, verifica e executa o bytecode (arquivos .class). JRE (Java Runtime Environment) é a JVM mais a biblioteca padrão de classes: é o necessário para executar programas Java. JDK (Java Development Kit) é o JRE mais as ferramentas de desenvolvimento, como o compilador javac, o jar, o javadoc e o depurador jdb: é o necessário para desenvolver. Um contém o outro: JDK ⊃ JRE ⊃ JVM.

EtapaO que aconteceArquivo
1. EdiçãoO programador escreve o código-fonte em um editor ou IDE.produz Ola.java
2. CompilaçãoO javac verifica sintaxe e tipos e traduz o fonte para bytecode.usa Ola.java, produz Ola.class
3. CargaO carregador de classes (class loader) da JVM lê o .class do disco e o coloca na memória.usa Ola.class
4. VerificaçãoO verificador de bytecode confere se o código é válido e não viola as regras de segurança da JVM.usa Ola.class
5. ExecuçãoA JVM executa o bytecode, interpretando-o e compilando os trechos mais usados para código nativo (JIT).usa Ola.class

Portabilidade: o compilador gera bytecode, que não depende de sistema operacional nem de processador. O mesmo .class roda em qualquer máquina que tenha uma JVM, porque é a JVM (específica de cada plataforma) que traduz o bytecode para o hardware local. Compila-se uma vez e executa-se em qualquer lugar (“write once, run anywhere”).

Explicação interativa

As três camadas, uma dentro da outra:

JDK (Java Development Kit) Para desenvolver: tudo do JRE e mais javac, jar, javadoc, jdb.
JRE (Java Runtime Environment) Para executar: a JVM e a biblioteca padrão (java.lang, java.util, javax.swing…).
JVM (Java Virtual Machine) Carrega, verifica e executa bytecode. Não entende .java, só .class.

Desde o Java 11 a Oracle não distribui um JRE separado: instala-se o JDK, que já traz o ambiente de execução (outros fornecedores, como o Adoptium, ainda oferecem pacotes só de JRE). A distinção conceitual continua valendo.

Use “Reproduzir” para ver a esteira levar o arquivo por todas as etapas, ou clique em uma etapa para ir direto a ela:

    E por que o mesmo arquivo serve para todos os sistemas:

    Ola.classum único arquivo de bytecode
    JVM para Windowstraduz para instruções x86-64
    JVM para Linuxtraduz para x86-64 ou ARM
    JVM para macOStraduz para Apple Silicon (ARM)

    Compare com C: um executável compilado para Windows não roda no Linux, é preciso recompilar o código-fonte. Em Java, o que muda de uma plataforma para outra é só a JVM; o bytecode é o mesmo.

    Enunciado

    Explique o papel de cada palavra da assinatura public static void main(String[] args). O que aconteceria se a palavra static fosse removida?

    Resposta
    PartePapel
    publicModificador de acesso: o método pode ser chamado de fora da classe e do pacote. A JVM precisa acessá-lo para iniciar o programa.
    staticO método pertence à classe, não a um objeto. Assim a JVM pode chamá-lo sem criar nenhum objeto, o que é necessário porque, no início do programa, nenhum objeto existe ainda.
    voidTipo de retorno: o método não devolve valor.
    mainNome que a JVM procura como ponto de entrada do programa.
    String[] argsParâmetro: array de String com os argumentos de linha de comando passados depois do nome da classe (ex.: java Programa a b faz args[0] ser "a"). O nome args é só convenção.

    Sem static: o código compila, mas o método deixa de ser um ponto de entrada válido no modelo tradicional. Ao executar, a JVM não tem um objeto para chamá-lo e encerra com Error: Main method is not static in class Ola, please define the main method as: public static void main(String[] args).

    Observação: a partir do Java 25 (JEP 512), o lançador aceita um main de instância. Se a classe tiver um construtor sem parâmetros não privado, a JVM cria o objeto e chama o main nele, e o programa roda normalmente.

    O que o programa Expressoes imprime
    
  
    Enunciado
    
  
    
    
    Sem executar, diga o que o programa abaixo imprime. Justifique as linhas 1, 2 e 6.
    

    public class Expressoes {
    public static void main(String[] args) {
        int x = 5;
        int y = x++;
        int z = ++x;
        System.out.println(x + " " + y + " " + z);                    // linha 1
        System.out.println(7 / 2 + " " + 7 / 2.0 + " " + 7 % 3);      // linha 2
        System.out.println((int) 9.99 + " " + (double) 7 / 2);         // linha 3
        boolean a = true, b = false;
        System.out.println((a ^ b) + " " + (a && !b) + " " + (a ^ true)); // l. 4
        int n = 15;
        System.out.println(n % 2 == 0 ? "par" : "ímpar");               // linha 5
        System.out.println(1 + 2 + "3" + 4 + 5);                        // linha 6
    }
}
    
  
    
  
    Resposta
    
  
    
    
    7 5 7
3 3.5 1
9 3.5
true true false
ímpar
3345
    
    
    Linha 1: y = x++ é pós-incremento: y recebe o valor antigo (5) e depois x vira 6. z = ++x é pré-incremento: x vira 7 primeiro e z recebe 7. Logo, x = 7, y = 5, z = 7.
    
    
    Linha 2: / e % têm precedência sobre +. 7 / 2 tem dois inteiros, então é divisão inteira: 3. 7 / 2.0 tem um double, então é divisão real: 3.5. 7 % 3 é o resto: 1.
    
    
    Linha 3: (int) 9.99 trunca para 9. O cast (double) se aplica só ao 7, então a conta é 7.0 / 2 = 3.5.
    
    
    Linha 4: true ^ false é true (XOR: lados diferentes); true && !false é true; true ^ true é false.
    
    
    Linha 5: 15 % 2 é 1, diferente de 0, então o ternário escolhe "ímpar".
    
    
    Linha 6: o + é avaliado da esquerda para a direita. 1 + 2 são dois int: soma 3. 3 + "3" envolve String: concatena, "33". Daí em diante tudo é concatenação: "334" e depois "3345".

      Escreva a classe Primo, cujo main lê um inteiro positivo n com Scanner, imprime todos os divisores de n e informa se n é primo (um número é primo quando tem exatamente dois divisores). Exemplo de execução:
      
    
      Digite um inteiro positivo: 12
Divisores de 12: 1 2 3 4 6 12
12 não é primo.
      
  
      
  
      Resposta
      
  
      

      import java.util.Scanner;

public class Primo {
    public static void main(String[] args) {
        Scanner sc = new Scanner(System.in);
        System.out.print("Digite um inteiro positivo: ");
        int n = sc.nextInt();

        int divisores = 0;
        System.out.print("Divisores de " + n + ":");
        for (int i = 1; i <= n; i++) {
            if (n % i == 0) {              // i divide n sem deixar resto
                System.out.print(" " + i);
                divisores++;
            }
        }
        System.out.println();

        if (divisores == 2) {
            System.out.println(n + " é primo.");
        } else {
            System.out.println(n + " não é primo.");
        }
        sc.close();
    }
}
      
  
      
  
      

      Explicação interativa
      
  
      
    
      A ideia central é o teste n % i == 0: i é divisor de n quando a divisão não deixa resto. O laço testa todos os candidatos de 1 até n, imprime os que passam e conta quantos foram. Depois do laço, a contagem decide: exatamente 2 divisores (1 e o próprio n) significa primo. Por isso o 1 não é primo: tem um só divisor.

      Soma dos ímpares com for, while e do-while
      
  
      Enunciado
      
  
      Calcule a soma dos números ímpares de 1 a 99 de três formas diferentes: com for, com while e com do-while. Qual é o resultado? Em que situação o do-while se comporta diferente do while?
      
  
      Resposta
      
  
      

      // com for
int soma1 = 0;
for (int i = 1; i <= 99; i += 2) {
    soma1 += i;
}

// com while
int soma2 = 0;
int j = 1;
while (j <= 99) {
    soma2 += j;
    j += 2;
}

// com do-while
int soma3 = 0;
int k = 1;
do {
    soma3 += k;
    k += 2;
} while (k <= 99);

System.out.println(soma1 + " " + soma2 + " " + soma3);   // 2500 2500 2500
      
    
      Resultado: 2500. São 50 números ímpares (1, 3, …, 99), e a soma dos k primeiros ímpares é k², ou seja, 50² = 2500.
      
    
      Diferença: o while testa a condição antes de executar o corpo; o do-while testa depois. Por isso, quando a condição já é falsa no início, o while não executa o corpo nenhuma vez e o do-while executa uma vez. Exemplo: começando com 101, o while deixa a soma em 0 e o do-while soma 101.
      
  
      
  
      

      Explicação interativa
      
  
      Rode cada laço. Depois mude o valor inicial para 101 e compare while com do-while.
      
  
      
    
      
      
      
      
    
      
    
      
      Valor inicial:
      
      
    
      
    
      
      
      
      
      
        
      
        
      
      
      
    
      
    
      
      
      
      
      
      
    
      
  
      
  
      Por que dá exatamente 2500: cada número ímpar acrescenta uma camada em forma de L a um quadrado. Mova o controle.
      
  
      
    
    
    
      
      
      
      
      
    
      
    
      A camada número k tem 2k − 1 quadradinhos, que é o k-ésimo ímpar. Somando os 50 primeiros ímpares (até 2 × 50 − 1 = 99), o quadrado fica 50 × 50 = 2500.

      Compra com JOptionPane
      
  
      Enunciado
      
  
      Usando JOptionPane, escreva um programa que peça ao usuário o preço de um produto e a quantidade comprada, mostre o valor total em uma caixa de mensagem e, em seguida, pergunte com uma caixa de confirmação se ele deseja finalizar a compra, exibindo “Compra finalizada.” ou “Compra cancelada.”. Por que é necessário converter o valor retornado por showInputDialog?
      
  
      Resposta
      
  
      

      import javax.swing.JOptionPane;

public class Compra {
    public static void main(String[] args) {
        String textoPreco = JOptionPane.showInputDialog("Preço do produto:");
        String textoQtd = JOptionPane.showInputDialog("Quantidade comprada:");

        double preco = Double.parseDouble(textoPreco);
        int quantidade = Integer.parseInt(textoQtd);
        double total = preco * quantidade;

        JOptionPane.showMessageDialog(null, "Valor total: R$ " + total);

        int resposta = JOptionPane.showConfirmDialog(null,
                "Deseja finalizar a compra?", "Confirmação",
                JOptionPane.YES_NO_OPTION);

        if (resposta == JOptionPane.YES_OPTION) {
            JOptionPane.showMessageDialog(null, "Compra finalizada.");
        } else {
            JOptionPane.showMessageDialog(null, "Compra cancelada.");
        }
    }
}
      
    
      Por que converter: showInputDialog sempre devolve uma String (ou null, se o usuário cancelar), mesmo que o usuário digite um número. Com Strings não dá para fazer contas: textoPreco * textoQtd nem compila, e + concatenaria em vez de somar ("10" + "2" dá "102"). Por isso o texto é convertido com Double.parseDouble e Integer.parseInt.
      
  
      
  
      

      Explicação interativa

      Identificadores válidos e convenções
      
  
      Enunciado
      
  
      
    
      Quais dos identificadores abaixo podem ser usados como nome de uma classe Java? Quais deles, além de válidos, seguem a convenção de nomes de classe?
      
    
      Welcome1 $valor _valor m_campoDeEntrada1 botao7 7botao campo de entrada class ContaCorrente
      
  
      
  
      Resposta
      
  
      
    
      
      
      IdentificadorVálido?Segue a convenção de classe?
      
      
        
      Welcome1SimSim
      
        
      $valorSimNão: começa com $ e minúscula
      
        
      _valorSimNão: começa com _ e minúscula
      
        
      m_campoDeEntrada1SimNão: começa com minúscula e usa _
      
        
      botao7SimNão: começa com minúscula
      
        
      7botaoNão: começa com dígito—
      
        
      campo de entradaNão: contém espaços—
      
        
      classNão: palavra reservada—
      
        
      ContaCorrenteSimSim
      
            
    
      
    
      Podem ser nomes de classe: Welcome1, $valor, _valor, m_campoDeEntrada1, botao7 e ContaCorrente. Desses, seguem a convenção apenas Welcome1 e ContaCorrente.
      
  
      
  
      

      Explicação interativa
      
  
      
    
      São dois filtros diferentes. A regra é imposta pelo compilador: o identificador começa com letra, $ ou _; depois pode ter letras, dígitos, $ e _; não pode ter espaços nem outros símbolos; e não pode ser palavra reservada (class, int, public…). Maiúsculas e minúsculas são diferentes.
      
    
      A convenção não é verificada pelo compilador, mas é seguida por todo programador Java: classes em UpperCamelCase (cada palavra começa com maiúscula, sem separadores), variáveis e métodos em lowerCamelCase e constantes em MAIUSCULAS_COM_SUBLINHADO. $ e _ são permitidos, mas evitados; o $ é usado por código gerado automaticamente.

      Classe Produto
      
  
      Enunciado
      
  
      
    
      Implemente a classe Produto com os atributos nome, preco e quantidade (em estoque) e:
      
    
      (a) um construtor Produto(String nome, double preco), em que o estoque começa em zero;
      
    (b) void adicionar(int qtd): soma qtd ao estoque; valores menores ou iguais a zero são ignorados;
      
    (c) boolean remover(int qtd): retira qtd do estoque e devolve true; se qtd for menor ou igual a zero ou maior que o estoque, não altera nada e devolve false;
      
    (d) double valorTotalEmEstoque() e String descricao(), no formato mostrado abaixo.
      
    
      O programa a seguir deve produzir a saída indicada:
      

      public class TesteProduto {
    public static void main(String[] args) {
        Produto tv = new Produto("TV", 900.0);
        tv.adicionar(5);
        System.out.println(tv.descricao());
        System.out.println(tv.remover(2));
        System.out.println(tv.remover(10));
        tv.adicionar(-3);
        System.out.println(tv.descricao());
    }
}
      
    
      TV, R$ 900.0, 5 unidades, total R$ 4500.0
true
false
TV, R$ 900.0, 3 unidades, total R$ 2700.0
      
  
      
  
      Resposta
      
  
      

      public class Produto {
    private String nome;
    private double preco;
    private int quantidade;

    // (a)
    public Produto(String nome, double preco) {
        this.nome = nome;
        this.preco = preco;
        this.quantidade = 0;               // estoque começa em zero
    }

    // (b)
    public void adicionar(int qtd) {
        if (qtd <= 0) {
            return;                        // ignora valores inválidos
        }
        quantidade += qtd;
    }

    // (c)
    public boolean remover(int qtd) {
        if (qtd <= 0 || qtd > quantidade) {
            return false;                  // não altera nada
        }
        quantidade -= qtd;
        return true;
    }

    // (d)
    public double valorTotalEmEstoque() {
        return preco * quantidade;
    }

    public String descricao() {
        return nome + ", R$ " + preco + ", " + quantidade
                + " unidades, total R$ " + valorTotalEmEstoque();
    }
}
      
  
      
  
      

      Explicação interativa
      
  
      
    
      Os atributos são private e só mudam pelos métodos, que garantem a regra “o estoque nunca fica negativo”. Isso é encapsulamento. Os métodos adicionar e remover usam cláusulas de guarda: testam primeiro os casos inválidos e saem imediatamente; o resto do método só roda quando está tudo certo.
      
    
      Na descricao(), concatenar um double produz 900.0 e 4500.0, com ponto e uma casa decimal, exatamente como na saída esperada. O valor total é calculado na hora, a partir de preco e quantidade, e não guardado como atributo: assim nunca fica desatualizado.

      O erro no construtor de Pessoa e a palavra this
      
  
      Enunciado
      
  
      
    
      O que o programa abaixo imprime? Explique o erro e corrija o construtor. Qual é o papel da palavra this?
      

      // Arquivo: Pessoa.java
public class Pessoa {
    private String nome;
    private int idade;

    public Pessoa(String nome, int idade) {
        nome = nome;
        this.idade = idade;
    }

    public String getNome() { return nome; }
    public int getIdade() { return idade; }
}

// Arquivo: TestePessoa.java
public class TestePessoa {
    public static void main(String[] args) {
        Pessoa p = new Pessoa("Ana", 20);
        System.out.println(p.getNome() + " " + p.getIdade());
    }
}
      
  
      
  
      Resposta
      
  
      
    
      Imprime:
      
    
      null 20
      
    
      Erro: dentro do construtor, o parâmetro nome tem o mesmo nome do atributo e o esconde (sombreamento). A linha nome = nome; atribui o parâmetro a ele mesmo, e o atributo nome do objeto nunca recebe valor, ficando com o valor padrão null. Já idade usa this e funciona. O compilador aceita o código, então o erro só aparece na execução.
      
    
      Correção:
      

      public Pessoa(String nome, int idade) {
    this.nome = nome;
    this.idade = idade;
}
      
    
      Com a correção, imprime Ana 20.
      
    
      Papel do this: é uma referência ao próprio objeto, aquele que está sendo construído ou que recebeu a chamada do método. this.nome significa “o atributo nome deste objeto”, o que diferencia o atributo do parâmetro de mesmo nome. Também é usado para chamar outro construtor da classe (this(...)) e para passar o próprio objeto como argumento.
      
  
      
  
      

      Explicação interativa
      
  
      Compare as duas versões do construtor. À esquerda, os parâmetros, que vivem na pilha só enquanto o construtor executa; à direita, o objeto criado no heap.
      
  
      
    
      
      
      
    
      
    
      
    
      
    
      Saída do TestePessoa
      
    
      
  
      
  
      Quando o construtor termina, os parâmetros desaparecem da pilha. Só sobrevive o que foi guardado no objeto. Por isso o valor "Ana" se perde na versão com erro.
      

      

      



      
  
      11
      A classe Caneta e o construtor padrão
      
  
      Enunciado
      
  
      
    
      Considere a classe Caneta sem nenhum construtor declarado.
      

      // Arquivo: Caneta.java
public class Caneta {
    String cor;
    int carga;
    boolean tampada;
}

// Arquivo: TesteCaneta.java
public class TesteCaneta {
    public static void main(String[] args) {
        Caneta c = new Caneta();
        System.out.println(c.cor + " " + c.carga + " " + c.tampada);
    }
}
      
    
      (a) Por que new Caneta() compila, se a classe não declara construtor? O que é impresso?
      
    (b) Se adicionarmos à classe o construtor public Caneta(String cor) { this.cor = cor; }, a linha new Caneta() continua compilando? Como permitir as duas formas de criação?
      
  
      
  
      Resposta
      
  
      
    
      (a) Quando uma classe não declara nenhum construtor, o compilador insere automaticamente o construtor padrão, sem parâmetros e sem corpo (public Caneta() { }). Os atributos recebem os valores padrão do tipo: String (referência) recebe null, int recebe 0 e boolean recebe false. Imprime:
      
    
      null 0 false
      
    
      (b) Não. O construtor padrão só é inserido quando a classe não declara nenhum construtor. Ao declarar Caneta(String cor), ele deixa de existir, e new Caneta() dá erro de compilação. Para permitir as duas formas, declara-se também o construtor sem parâmetros (sobrecarga):
      

      public class Caneta {
    String cor;
    int carga;
    boolean tampada;

    public Caneta() {
    }

    public Caneta(String cor) {
        this.cor = cor;
    }
}
      
  
      
  
      

      Explicação interativa
      
  
      Mude a versão da classe e veja quais chamadas compilam:
      
  
      
    
      
      
      
      
    
      
    
      
    
      
  
      
  
      Valores padrão de todos os tipos de atributo:
      
  
      
    
      Tipo do atributoValor inicial se ninguém atribuir
      
    
      
      byte, short, int, long0
      
      
      float, double0.0
      
      
      charo caractere de código 0 ('\u0000')
      
      
      booleanfalse
      
      
      Referências (String, arrays, qualquer objeto)null
      
          
  
      
  
      Valores padrão valem só para atributos. Variáveis locais (declaradas dentro de métodos) não recebem valor padrão: usá-las sem atribuir antes é erro de compilação.
      

      

      



      
  
      12
      Referências e passagem por valor
      
  
      Enunciado
      
  
      
    
      Considere a classe Autor, com atributo nome, construtor, getNome() e setNome(String). Diga o que é impresso em cada linha marcada e justifique.
      

      // Arquivo: Autor.java
public class Autor {
    private String nome;
    public Autor(String nome) { this.nome = nome; }
    public String getNome() { return nome; }
    public void setNome(String nome) { this.nome = nome; }
}

// Arquivo: TesteReferencias.java
public class TesteReferencias {
    static void renomear(Autor a) { a.setNome("Carlos"); }
    static void substituir(Autor a) { a = new Autor("Diego"); a.setNome("Eva"); }
    static void dobrar(int x) { x = x * 2; }

    public static void main(String[] args) {
        Autor a1 = new Autor("Ana");
        Autor a2 = new Autor("Ana");
        Autor a3 = a1;
        System.out.println(a1 == a2);                            // (a)
        System.out.println(a1 == a3);                            // (b)
        System.out.println(a1.getNome().equals(a2.getNome()));   // (c)
        a3.setNome("Beatriz");
        System.out.println(a1.getNome());                        // (d)
        renomear(a2);
        System.out.println(a2.getNome());                        // (e)
        substituir(a2);
        System.out.println(a2.getNome());                        // (f)
        int n = 10;
        dobrar(n);
        System.out.println(n);                                   // (g)
    }
}
      
    
      Desenhe também a pilha (stack) e o heap logo após a linha Autor a3 = a1;.
      
  
      
  
      Resposta
      
  
      
    
      
      
      ImprimeJustificativa
      
      
        
      (a)false== entre referências compara se apontam para o mesmo objeto. a1 e a2 vêm de dois new diferentes: são objetos distintos, mesmo com o mesmo nome.
      
        
      (b)truea3 = a1 copiou a referência: as duas variáveis apontam para o mesmo objeto.
      
        
      (c)trueequals da String compara o conteúdo: os dois nomes são "Ana".
      
        
      (d)BeatrizO nome foi alterado através de a3, mas o objeto é o mesmo de a1.
      
        
      (e)CarlosO parâmetro a recebe uma cópia da referência de a2 e aponta para o mesmo objeto; setNome altera esse objeto.
      
        
      (f)CarlosDentro de substituir, o parâmetro a passa a apontar para um objeto novo (“Diego”, depois “Eva”). Só a cópia mudou; a2 continua apontando para o objeto antigo.
      
        
      (g)10Tipos primitivos são passados por cópia do valor: x vira 20 dentro de dobrar, mas n não muda.
      
            
    
      
    
      Em Java toda passagem é por valor. Quando o argumento é uma referência, o valor copiado é a referência: o método pode alterar o objeto apontado (e), mas reatribuir o parâmetro não afeta a variável de quem chamou (f).
      
    
      Pilha e heap logo após Autor a3 = a1;
      
    
      
    
      Há dois objetos Autor no heap e três variáveis do tipo Autor na pilha; a1 e a3 apontam para o mesmo objeto. No desenho, o nome aparece dentro do objeto para simplificar. Na verdade, nome também é uma referência para um objeto String, e como "Ana" é um literal, os dois objetos apontam para a mesma String no pool de Strings.

      13
      Objetos que referenciam objetos: Carro e Pessoa
      
  
      Enunciado
      
  
      
    
      Implemente as classes Pessoa (atributo nome, construtor e getNome()) e Carro, com os atributos modelo e dono (do tipo Pessoa, que pode ser null) e:
      
    
      (a) construtor Carro(String modelo, Pessoa dono);
      
    (b) String descricao(): "<modelo> - dono: <nome>" ou, se não houver dono, "<modelo> - sem dono";
      
    (c) boolean transferirPara(Pessoa novo): devolve false se novo for null ou for o mesmo dono atual (use ==); caso contrário, troca o dono e devolve true;
      
    (d) boolean mesmoDonoQue(Carro outro): verdadeiro se os dois carros têm dono e o dono é o mesmo objeto.
      

      // Arquivo: TesteCarro.java
public class TesteCarro {
    public static void main(String[] args) {
        Pessoa ana = new Pessoa("Ana");
        Pessoa bia = new Pessoa("Bia");
        Pessoa outraAna = new Pessoa("Ana");
        Carro gol = new Carro("Gol", ana);
        Carro uno = new Carro("Uno", null);
        Carro kwid = new Carro("Kwid", outraAna);
        System.out.println(gol.descricao());
        System.out.println(uno.descricao());
        System.out.println(gol.mesmoDonoQue(kwid));
        System.out.println(uno.transferirPara(ana));
        System.out.println(gol.mesmoDonoQue(uno));
        System.out.println(gol.transferirPara(ana));
        System.out.println(gol.transferirPara(null));
        System.out.println(gol.transferirPara(bia));
        System.out.println(gol.descricao() + " | " + uno.descricao());
    }
}
      
    
      Qual saída você espera? Por que gol.mesmoDonoQue(kwid) é falso, se os dois donos se chamam Ana?
      
  
      
  
      Resposta
      
  
      

      // Arquivo: Pessoa.java
public class Pessoa {
    private String nome;

    public Pessoa(String nome) {
        this.nome = nome;
    }

    public String getNome() {
        return nome;
    }
}

// Arquivo: Carro.java
public class Carro {
    private String modelo;
    private Pessoa dono;                         // pode ser null

    // (a)
    public Carro(String modelo, Pessoa dono) {
        this.modelo = modelo;
        this.dono = dono;
    }

    // (b)
    public String descricao() {
        if (dono == null) {
            return modelo + " - sem dono";
        }
        return modelo + " - dono: " + dono.getNome();
    }

    // (c)
    public boolean transferirPara(Pessoa novo) {
        if (novo == null || novo == dono) {
            return false;
        }
        dono = novo;
        return true;
    }

    // (d)
    public boolean mesmoDonoQue(Carro outro) {
        return outro != null && dono != null && outro.dono != null
                && dono == outro.dono;
    }
}
      
    
      Saída:
      
    
      Gol - dono: Ana
Uno - sem dono
false
true
true
false
false
true
Gol - dono: Bia | Uno - dono: Ana
      
    
      Por que gol.mesmoDonoQue(kwid) é falso: o método compara os donos com ==, que verifica se são o mesmo objeto, não se têm o mesmo nome. ana e outraAna foram criadas por dois new diferentes, então são dois objetos distintos no heap que por acaso guardam o mesmo nome. Para comparar pelo nome seria preciso usar dono.getNome().equals(outro.dono.getNome()).
      
  
      
  
      

      Explicação interativa
      
  
      
    
      Dois detalhes do código: sempre se testa null antes de chamar um método pela referência (chamar getNome() em null lança NullPointerException), e o && é de curto-circuito: se o lado esquerdo for false, o direito nem é avaliado. Por isso a ordem dos testes em mesmoDonoQue importa. Também é permitido acessar outro.dono, mesmo sendo private, porque a restrição é por classe, não por objeto.
